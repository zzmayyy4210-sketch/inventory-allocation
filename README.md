# 店铺库存分配与检查 Skill

**只补缺货链接，也能找齐共用实物的其他链接，避免重复分配库存。**

适用于：OMS 只能导出单品库存，店铺既有单品又有组合装，而且店铺库存需要人工修改的场景。

这是给 AI 使用的 skill，包含工作说明和计算脚本。无需前端。用户把表格提供给支持读取文件、执行 Python 的 AI 环境，获得查询清单、建议填写清单和库存核对结果，然后手动修改店铺后台。

## 最常用：只补缺货商品

假设你只想补“组合 1（A＋B）”，不想重新分配全店库存：

1. 提供最新 OMS 库存表，以及完整的链接组成表。
2. 告诉 AI 本次只修改哪个链接。
3. AI 自动找出所有使用 A 或 B 的其他链接，生成一张待查询清单。
4. 你按清单到店铺后台查询当前可售库存，填回给 AI。
5. AI 保留其他链接库存，扣除它们占用的实物，只为目标链接计算建议数量。
6. 核对通过后，你照着最终清单手动修改后台。

**你不必自己找关联组合，也不必查全店。后台无法自动读取时，相关链接当前库存仍需手动查询。**

### 一个例子

仓库有 A 10 个、B 20 个。你要补 A＋B 套餐，另有 A 单卖链接当前可售 4 件、B＋C 套餐当前可售 8 套（每套用一个 B）。

| 单品 | 仓库可用 | 其他链接占用 | 留给目标的数量 |
| --- | ---: | ---: | ---: |
| A | 10 | 4 | 6 |
| B | 20 | 8 | 12 |

A＋B 套餐最终最多设置 **6 套**，不是增加 6 套。B＋C 链接的库存不变，因此不需要继续查询只使用 C 的其他链接。本次只核对 A、B，不代表全店其他单品都通过检查。

## 开始使用

### 在 Codex 中安装

可把仓库地址提供给带 skill-installer 的 Codex，并说：

> 请将这个 GitHub 仓库根目录的 inventory-allocation skill 安装到我的个人 skills 目录。安装完成后告诉我如何调用。

也可以下载仓库 ZIP 并解压，把包含 `SKILL.md`、`scripts`、`assets` 的文件夹命名为 `inventory-allocation`，作为个人 skill 安装。具体安装位置和发现方式以当前环境为准；[官方 skill 文档](https://learn.chatgpt.com/docs/build-skills)介绍了 skill 结构与使用方式。

安装后，在聊天里调用 `$inventory-allocation` 并提供表格。若当前环境不支持原生安装 skill，可把整个文件夹放入该 AI 能读取的工作目录，明确让它先阅读 `SKILL.md` 再处理；这不等同于所有聊天产品都能原生安装。

### 第一次对 AI 说什么

```text
使用 $inventory-allocation。
这是最新 OMS 库存表和完整链接组成表。
本次只补缺货链接：组合 1（请替换为真实链接编号）。
其他链接的库存保持不变。
请先识别表格列名，再列出我需要去后台查询的相关链接。
数量没有提供前不要猜测，也不要直接计算可填写库存。
```

收到待查询清单、查询完成后，再说：

```text
这是你列出的相关链接当前可售库存。
请扣除它们占用的实物，计算目标链接的最终建议库存。
输出填写清单和逐单品核对表，明确是否通过检查。
```

### 我改了建议数量，想再检查

```text
这是我调整后的计划库存，请只检查，不要替我改数量。
指出哪些单品超出了实物库存、各超多少，以及哪些链接占用了它们。
```

### 我要重新分配全部链接

```text
使用 $inventory-allocation，根据这两张最新表重新分配全部链接库存。
没有经营优先级，按各链接可售份数尽量平均分配。
输出完整填写清单和逐单品核对表。
```

## 表格需要包含什么

**不必改成模板格式。** AI 应先识别原表列名，不确定时询问，不得猜测商品对应关系。

| 资料 | 必要内容 | 什么时候提供 |
| --- | --- | --- |
| 单品库存 | 单品唯一编号、可分配实物数量 | 每次使用提供最新数据 |
| 完整链接组成 | 链接编号、所含单品编号、每份各用几个 | 首次提供，商品组成变更后更新 |
| 相关链接当前库存 | 链接编号、后台当前可售份数 | 局部补库存时，AI 列清单后填写 |
| 修改后的计划库存 | 链接编号、计划份数 | 要重新检查时 |

单品销售链接也要列入组成表，每份用量为 1。一个组合含多个单品时可以占多行。单品编号必须能对应，组合里同一个单品需要两件时用量应为 2。

示例模板都在 [assets](assets/) 中，数据全部虚构：

- [单品库存](assets/单品库存模板.csv)
- [链接组成](assets/链接组成模板.csv)
- [计划库存](assets/计划库存模板.csv)
- [相关链接当前库存](assets/相关链接当前库存模板.csv)

## 默认分配规则

全量分配或多个目标链接同时补货时，各链接轮流分配一份；无法再组成完整一份的链接停止，其余继续。余数按链接编号字符顺序处理。公平指可售份数尽量平均，不是实物耗用数相同。受组合缺货约束，最后各链接数量可能不同。

局部补货时，其他链接占用先扣除，剩下的实物才参加目标分配。若其他链接已经占超库存，会停止生成建议并报告缺口。

## 使用范围与数据边界

- 仅根据输入时点的数量计算；期间订单、补货或其他渠道占用变化后需要重新核对。
- OMS 应提供可分配库存。已下单、冻结、其他渠道预留是否已扣除，要先确认口径，避免漏扣或重复扣除。
- 组合关系必须覆盖所有共用相关实物的销售链接。漏掉链接会漏算占用。
- 缺少相关链接库存时，不会把它当作零。
- 本仓库只保存 skill、虚构示例和测试。真实业务表格在使用者获准的环境处理，无需提交到 GitHub。
- 尚未用真实业务表格验证；复杂排版、商品别名、混合单位等需第一次使用时确认映射。

## 文件说明与验证

- `SKILL.md`：AI 工作说明。
- `scripts/allocate.py`：整数分配、关联查询、局部分配和超卖核对。
- `assets/`：虚构数据模板。
- `tests/test_allocate.py`：计算规则验证。

开发者可以在 Python 3 环境运行 `python -m unittest discover -s tests -v`。计算模块仅用 Python 标准库；Excel 等文件的读取能力由实际 AI 环境提供。
